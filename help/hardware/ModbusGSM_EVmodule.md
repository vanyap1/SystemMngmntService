## 1. Як підключитись

### Modbus RTU (RS485)

| Параметр | Значення за замовчуванням | Де змінити |
|---|---|---|
| Адреса пристрою | **1** | HR3 або `set addr` |
| Швидкість | **115200** | HR45 (÷100) або `set baud`, діє після збереження й перезавантаження |
| Формат | 8N1 (8 біт, без парності, 1 стоп-біт) | — |
| Пауза між кадрами | ≥ 3,5 символу, не менше 1,75 мс | — |
| Таймаут відповіді майстра | рекомендовано ≥ 100 мс | — |

- Адреса **0** — broadcast: запис виконується, відповіді немає.
- На запити з чужою адресою пристрій мовчить.

> **Важливо.** За замовчуванням увімкнений текстовий лог у RS485 (рядки на кшталт `[ 12] gsm: ...`).
> Вони йдуть у шину без запиту й можуть зіпсувати обмін з Modbus-майстром. Перед роботою
> з SCADA/ПЛК вимкни лог: HR44 біт 0 = 0 (або консоль `set log 0`), потім HR2 = 1 (зберегти).

### Modbus TCP (через GSM)

Пристрій — **TCP-клієнт**: у мобільних мережах зазвичай немає публічної IP, тому він сам
підключається до сервера `host:port` і тримає з'єднання. Сервер шле в це з'єднання звичайні
кадри Modbus TCP (MBAP-заголовок + PDU). Режим у SCADA зазвичай називається «reverse connection» /
«зворотне з'єднання».

| Unit ID у запиті | Хто відповідає |
|---|---|
| = адреса пристрою (HR3) або **255** | сам шлюз (регістри цього документа) |
| будь-який інший (1..247) | пристрій з цією адресою на RS485: шлюз пересилає запит як RTU і повертає відповідь |
| 0 | broadcast на RS485, без відповіді |

Якщо пристрій на RS485 не відповів за HR46 мс (за замовчуванням 500), сервер отримає виняток
**0x0B** (Gateway Target Device Failed to Respond).

Налаштування TCP: сервер — HR82…105, порт — HR47, увімкнення — HR44 біт 3, потім HR2 = 1 (зберегти)
і HR2 = 6 (перепідключитись). Стан з'єднання: IR3 = 6.

## 2. Функції та формати

| Код | Функція | Об'єкти |
|---|---|---|
| 01 | Read Coils | виходи IO |
| 02 | Read Discrete Inputs | рівні на пінах IO |
| 03 | Read Holding Registers | налаштування, керування |
| 04 | Read Input Registers | стан (тільки читання) |
| 05 | Write Single Coil | вихід IO |
| 06 | Write Single Register | налаштування, команда |
| 15 (0x0F) | Write Multiple Coils | виходи IO |
| 16 (0x10) | Write Multiple Registers | налаштування, розклад, рядки |

**Адресація — з нуля** (так, як адреса передається в кадрі). У програмах, що рахують з 1
(mbpoll, деякі SCADA з адресами 3xxxx/4xxxx), додавай 1: IR3 = 30004, HR2 = 40003.

**Формати даних**

- 16-бітні значення — беззнакові, крім HR6 (знакове, доповнювальний код).
- 32-бітні значення займають два регістри, **старше слово першим** (порядок ABCD / big-endian).
- Рядки: 2 символи ASCII на регістр, **старший байт — перший символ**, кінець рядка — байт 0.
  Приклад: `"internet"` → `0x696E 0x7465 0x726E 0x6574 0x0000 …`
- Бітові маски IO: біт 0 = IO0 … біт 3 = IO3.

**Винятки**

| Код | Коли |
|---|---|
| 01 Illegal Function | непідтримувана функція |
| 02 Illegal Data Address | регістр/coil поза картою (у групових запитах — якщо хоч один поза картою) |
| 03 Illegal Data Value | неприпустиме значення (наприклад, хвилина 75, швидкість 12345, IO не в режимі «вихід» для HR40…43) |
| 0B Gateway Target Failed | (лише TCP) пристрій на RS485 не відповів |

## 3. Карта регістрів

### 3.1 Coils (01 / 05 / 15) і Discrete Inputs (02)

| Адреса | Coil (читання/запис) | Discrete input (читання) |
|---|---|---|
| 0 | вихід IO0 (роз'єм NFC, p3) | рівень на піні IO0 |
| 1 | вихід IO1 (p5) | рівень на піні IO1 |
| 2 | вихід IO2 (p7) | рівень на піні IO2 |
| 3 | вихід IO3 (p9) | рівень на піні IO3 |
| 16 | вихід DO0 (порт дисплея, d5) | — |
| 17 | DO1 (d6) | — |
| 18 | DO2 (d7) | — |
| 19 | DO3 (d8) | — |
| 20 | DO4 (RS) | — |
| 21 | DO5 (RW) | — |
| 22 | DO6 (EN) | — |

Адреси 4–15 не існують: груповий запит, що їх зачіпає, отримає виняток 02 — читай блоки 0–3 і 16–22 окремо.

Coil керує піном, лише коли канал у режимі «вихід» (IO — див. розділ 4, порт дисплея — розділ 5).
Інакше записаний стан запам'ятовується і з'явиться на піні після перемикання режиму.

### 3.2 Input registers (04, тільки читання)

| Адр. | Назва | Значення |
|---|---|---|
| 0 | Версія | 0x0100 = 1.00 |
| 1–2 | Час роботи | секунди з моменту старту, 32 біт |
| 3 | Стан GSM | 0 немає модема · 1 ініціалізація · 2 помилка SIM · 3 пошук мережі · 4 у мережі · 5 є інтернет (GPRS) · 6 з'єднано з сервером |
| 4 | Сигнал | CSQ 0..31 (≥ 15 — добре), 99 — невідомо |
| 5 | Реєстрація | 0 ні · 1 домашня мережа · 2 пошук · 3 відмова · 5 роумінг |
| 6 | Входи | рівні на пінах IO, маска |
| 7 | Виходи | задані стани виходів, маска |
| 8–9 | Час UTC | Unix-секунди, 32 біт |
| 10 | Час встановлено | 0 / 1 |
| 11 | Лічильник RTU | прийняті RTU-запити до цього пристрою |
| 12 | Помилки RTU | кадри з помилкою CRC |
| 13 | Лічильник TCP | запити через GSM |
| 14 | Таймаути шлюзу | RS485-пристрій не відповів |
| 15 | Помилки | біти: 0 EEPROM не знайдено · 1 час не встановлено · 2 кварц RTC не працює · 3 SIM · 4 модем не відповідає |
| 16 | Рік | місцевий час |
| 17 | Місяць, день | місяць × 256 + день |
| 18 | Година, хвилина | година × 256 + хвилина |
| 19 | Секунда, день тижня | секунда × 256 + день тижня (1 = пн … 7 = нд) |
| 20–29 | IMEI | рядок |
| 30–37 | IP-адреса | рядок (порожній без GPRS) |
| 38–49 | Оператор | рядок, наприклад `MTS UKR` |

Лічильники 11–14 — 16 біт, після 65535 переходять у 0; скидаються при перезавантаженні.

### 3.3 Holding registers (03 / 06 / 16)

Зміни діють одразу, але **в EEPROM потрапляють лише після команди HR2 = 1**. Без збереження
після перезавантаження повернуться попередні значення. Винятки: HR0, HR2, HR4–5, HR40–43, HR49 —
це дії, вони не зберігаються.

| Адр. | Назва | Значення | Зберігається |
|---|---|---|---|
| 0 | Виходи IO | маска станів виходів IO0..IO3 | ні (див. HR48) |
| 1 | Режими IO (усі разом) | по 4 біти на IO: IO0 — біти 0..3, IO1 — 4..7, IO2 — 8..11, IO3 — 12..15. Значення: 0 вхід · 1 вхід з підтяжкою вгору · 2 вхід з підтяжкою вниз · 3 вихід. Те саме, що HR153–156 | так |
| 2 | **Команда** | див. 3.4; читається як 0 | — |
| 3 | Адреса Modbus | 1..247, діє з наступного запиту | так |
| 4–5 | Час UTC | Unix-секунди; записувати 4, потім 5 (або обидва одним FC16) | RTC |
| 6 | Часовий пояс | хвилини від UTC, знакове (Київ: 120) | так |
| 7 | Літній час | 1 — за правилом ЄС, 0 — ні | так |
| 8–39 | Розклад | 8 записів × 4 регістри, див. 3.5 | так |
| 40–43 | Імпульс | записати N секунд → IO0..IO3 увімкнеться на N с; 0 — вимкнути. Лише для IO в режимі «вихід» | ні |
| 44 | Прапорці | біт 0 лог у RS485 · 1 резерв (дисплей тепер — HR150) · 2 GPRS · 3 TCP до сервера · 4 SMS-команди · 5 синхронізація часу (NTP) | так |
| 45 | Швидкість RS485 | ÷100: 96, 192, 384, 576, 1152. Діє після збереження й перезавантаження | так |
| 46 | Таймаут шлюзу | мс, 50..5000 | так |
| 47 | Порт сервера | 1..65535 | так |
| 48 | Виходи після старту | маска | так |
| 49 | Тест світлодіодів | 0 — світлодіодами керує контролер; N = 1..16 — горить лише світлодіод на виході N ланцюжка 595 | ні |
| 50–65 | APN | рядок, 32 символи | так |
| 66–73 | Логін APN | 16 символів | так |
| 74–81 | Пароль APN | 16 символів, **читається як 0** | так |
| 82–105 | Сервер | IP або домен, 48 символів | так |
| 106–121 | NTP-сервер | 32 символи | так |
| 122–125 | PIN SIM | 8 символів, **читається як 0** | так |
| 126–133 | Номер SMS 1 | 16 символів | так |
| 134–141 | Номер SMS 2 | | так |
| 142–149 | Номер SMS 3 | | так |
| 150 | Режим порту дисплея | 0 вимкнено (піни high-Z) · 1 дисплей HD44780 · 2 виходи DO0..DO6. Діє одразу | так |
| 151 | Виходи DO | маска DO0..DO6 (біт 0 = DO0) | ні (див. HR152) |
| 152 | DO після старту | маска | так |
| 153 | Режим IO0 | 0 вхід · 1 вхід з підтяжкою вгору · 2 вхід з підтяжкою вниз · 3 вихід | так |
| 154 | Режим IO1 | | так |
| 155 | Режим IO2 | | так |
| 156 | Режим IO3 | | так |

### 3.4 Команди (запис у HR2)

| Значення | Дія |
|---|---|
| 1 | Зберегти налаштування в EEPROM |
| 2 | Перезавантажити пристрій |
| 3 | Скинути налаштування до заводських (зберігається, потім перезавантаження) |
| 4 | Тестовий писк |
| 5 | Синхронізувати час через інтернет зараз |
| 6 | Перепідключити GPRS/TCP (після зміни APN або сервера) |
| 7 | Перезапуск живлення модема (вимкнути на 3 с і ввімкнути) |

На команди 2 і 3 відповідь ще приходить, перезавантаження — через ~0,2–1 с.

### 3.5 Розклад (HR8…HR39)

8 записів, запис n займає регістри `8 + 4n` … `11 + 4n`:

| Зсув | Вміст |
|---|---|
| +0 | біт 15 — запис увімкнено · біти 8..9 — дія (0 вимкнути · 1 увімкнути · 2 перемкнути · 3 імпульс) · біти 0..3 — канал: 0..3 = IO0..IO3, 4..10 = DO0..DO6 |
| +1 | година × 256 + хвилина (місцевий час) |
| +2 | дні тижня: біт 0 = пн … біт 6 = нд (0x7F — щодня, 0x1F — будні, 0x60 — вихідні) |
| +3 | тривалість імпульсу, с (для дії 3) |

Розклад виконується лише коли час встановлено (IR10 = 1) і канал у режимі «вихід».

Приклад — запис 0: щодня о 06:00 імпульс 900 с (15 хв) на IO2:
`HR8 = 0x8302`, `HR9 = 0x0600`, `HR10 = 0x007F`, `HR11 = 900`.

## 4. Універсальні IO (роз'єм NFC)

4 піни роз'єму NFC — IO0..IO3. Кожен можна зробити входом або виходом.

| IO | Пін роз'єму | Пін МК |
|---|---|---|
| IO0 | p3 | PB2 |
| IO1 | p5 | PB1 |
| IO2 | p7 | PB11 |
| IO3 | p9 | PB10 |

Після старту всі IO — входи без підтяжки (безпечний стан), доки режим не задано й не збережено.

**Режим:** HR153…156 (по регістру на IO) — `0` вхід, `1` вхід з підтяжкою вгору (для кнопки/контакту
на GND), `2` вхід з підтяжкою вниз, `3` вихід. Зберегти: HR2 = 1.

**Читання:**
- рівень на піні — Discrete input 0…3 (FC02) або маска IR6 (FC04);
- для виходу — заданий стан: coil 0…3 (FC01) або маска IR7 / HR0.

**Запис (лише в режимі «вихід»):** coil 0…3 (FC05/FC15), маска HR0, імпульс N секунд — HR40…43.

## 5. Порт дисплея як виходи

7 пінів роз'єму дисплея можна використати як **виходи** DO0…DO6 (входом вони бути не можуть).

| DO | Підпис на роз'ємі | Пін МК | Coil |
|---|---|---|---|
| DO0 | d5 | PA3 | 16 |
| DO1 | d6 | PA2 | 17 |
| DO2 | d7 | PA1 | 18 |
| DO3 | d8 | PA0 | 19 |
| DO4 | RS | PA5 | 20 |
| DO5 | RW | PA6 | 21 |
| DO6 | EN | PA7 | 22 |

1. Перемкнути порт у режим виходів: HR150 = 2 (діє одразу; HR2 = 1 — зберегти).
2. Керувати: coil 16…22 (FC05/FC15) або маскою HR151.
3. Стан після старту: HR152 (маска), зберегти HR2 = 1.

HR150 = 1 віддає порт дисплею HD44780, HR150 = 0 — піни у високоімпедансному стані.
DO можна керувати і з розкладу (канали 4…10) та SMS (`OUT4 ON` … `OUT10 OFF`).

## 6. Світлодіоди

| LED | Колір | Що показує |
|---|---|---|
| 1 | зелений | **Робота.** Короткий спалах раз на секунду — прошивка працює. Не блимає — зависла (watchdog перезапустить через 8 с) |
| 2 | жовтий | **GSM.** Не світить — модем не відповідає · часто блимає — запуск модема / пошук мережі · подвійний спалах — проблема з SIM · повільно блимає (1 с / 1 с) — у мережі · світить — є інтернет (GPRS) |
| 3 | зелений | **Сервер.** Не світить — TCP вимкнено · блимає — підключається · світить — з'єднано (гасне на мить при обміні даними) |
| 4 | жовтий | **Modbus.** Короткий спалах на кожен запит — по RS485 чи через GSM |
| 5 | червоний | **Помилка.** Світить — є помилка (EEPROM, SIM, модем, кварц RTC — деталі в IR15) · рідко блимає — час не встановлено |

Перевірити світлодіоди: HR49 = 1…5 — горить лише відповідний світлодіод; HR49 = 0 — світлодіодами
знову керує контролер.

### 7.1 Готові кадри RTU (адреса 1, CRC пораховано)

| Дія | Запит (hex) |
|---|---|
| Прочитати стан (IR0…19) | `01 04 00 00 00 14 F0 05` |
| Прочитати стан GSM, сигнал, реєстрацію (IR3…5) | `01 04 00 03 00 03 40 0B` |
| Прочитати HR0…7 | `01 03 00 00 00 08 44 0C` |
| IO2 у режим «вихід» (HR155 = 3) | `01 06 00 9B 00 03 B8 24` |
| Прочитати режими IO0…IO3 (HR153…156) | `01 03 00 99 00 04 94 26` |
| IO2 і IO3 у режим «вихід» разом (HR1 = 0x3300) | `01 06 00 01 33 00 CC FA` |
| Увімкнути IO2 (coil 2) | `01 05 00 02 FF 00 2D FA` |
| Вимкнути IO2 | `01 05 00 02 00 00 6C 0A` |
| Прочитати виходи (coils 0…3) | `01 01 00 00 00 04 3D C9` |
| Прочитати входи (DI 0…3) | `01 02 00 00 00 04 79 C9` |
| Рівні входів маскою (IR6) | `01 04 00 06 00 01 D1 CB` |
| Порт дисплея → виходи (HR150 = 2) | `01 06 00 96 00 02 E8 27` |
| Увімкнути DO0 (coil 16) | `01 05 00 10 FF 00 8D FF` |
| DO0 і DO6 увімкнути маскою (HR151 = 0x41) | `01 06 00 97 00 41 F8 16` |
| Прочитати DO0…DO6 (coils 16…22) | `01 01 00 10 00 07 7C 0D` |
| Імпульс 10 с на IO1 (HR41 = 10) | `01 06 00 29 00 0A D8 05` |
| Розклад, запис 0 (FC16, приклад з 3.5) | `01 10 00 08 00 04 08 83 02 06 00 00 7F 03 84 0D 3D` |
| Зберегти налаштування (HR2 = 1) | `01 06 00 02 00 01 E9 CA` |
| Перезапустити модем (HR2 = 7) | `01 06 00 02 00 07 69 C8` |
| Тест: світлодіод 3 (HR49 = 3) | `01 06 00 31 00 03 98 04` |
| Світлодіодами знову керує контролер (HR49 = 0) | `01 06 00 31 00 00 D8 05` |
| Неіснуючий регістр → виняток 02 | `01 03 01 F4 00 01 C4 04` → `01 83 02 C0 F1` |

### 7.2 mbpoll

[mbpoll](https://github.com/epsilonrt/mbpoll) рахує адреси з 1 (`-r 1` = регістр 0). Тип: `-t 0` coil,
`-t 1` discrete input, `-t 3` input register, `-t 4` holding register.

```sh
P="-m rtu -a 1 -b 115200 -P none -1 COM26"
mbpoll $P -t 3 -r 1 -c 20                 # стан
mbpoll $P -t 4 -r 156 3                   # HR155 = 3: IO2 — вихід
mbpoll $P -t 0 -r 3 1                     # увімкнути IO2 (coil 2)
mbpoll $P -t 1 -r 1 -c 4                  # прочитати входи IO0..IO3
mbpoll $P -t 4 -r 151 2                   # HR150 = 2: порт дисплея — виходи
mbpoll $P -t 0 -r 17 1                    # увімкнути DO0 (coil 16)
mbpoll $P -t 4 -r 45 0x0034               # HR44: GPRS + SMS + NTP, лог вимкнено
mbpoll $P -t 4 -r 3 1                     # HR2 = 1: зберегти
```

### 7.3 Python (pymodbus 3.x)

```python
from pymodbus.client import ModbusSerialClient

c = ModbusSerialClient(port="COM26", baudrate=115200, parity="N", stopbits=1, timeout=0.5)
c.connect()
U = 1  # адреса пристрою

def regs_to_str(regs):
    b = bytes(x for r in regs for x in (r >> 8, r & 0xFF))
    return b.split(b"\0")[0].decode()

def str_to_regs(s, n):
    b = s.encode().ljust(n * 2, b"\0")[: n * 2]
    return [(b[i] << 8) | b[i + 1] for i in range(0, n * 2, 2)]

# --- стан ---
ir = c.read_input_registers(0, count=50, slave=U).registers
states = ["немає модема", "ініціалізація", "помилка SIM", "пошук мережі",
          "у мережі", "інтернет", "з'єднано з сервером"]
print("GSM:", states[ir[3]], "CSQ:", ir[4])
print("IMEI:", regs_to_str(ir[20:30]), "IP:", regs_to_str(ir[30:38]),
      "оператор:", regs_to_str(ir[38:50]))
print("час: %04d-%02d-%02d %02d:%02d" % (ir[16], ir[17] >> 8, ir[17] & 255, ir[18] >> 8, ir[18] & 255))

# --- IO: IO0 — вхід з підтяжкою (контакт на GND), IO2 — вихід ---
c.write_register(153, 1, slave=U)           # IO0 -> вхід з підтяжкою вгору
c.write_register(155, 3, slave=U)           # IO2 -> вихід
c.write_coil(2, True, slave=U)              # увімкнути IO2
print("IO0..3:", c.read_discrete_inputs(0, count=4, slave=U).bits[:4])

# --- порт дисплея як виходи ---
c.write_register(150, 2, slave=U)           # режим "виходи"
c.write_coil(16, True, slave=U)             # DO0 (d5) увімкнути
c.write_register(151, 0b1000001, slave=U)   # DO0 і DO6 увімкнути, решта вимкнути

# --- розклад: будні о 08:00 увімкнути IO3, о 18:30 вимкнути ---
c.write_register(156, 3, slave=U)           # IO3 — вихід
c.write_registers(12, [0x8000 | (1 << 8) | 3, (8 << 8) | 0, 0x1F, 0], slave=U)    # запис 1
c.write_registers(16, [0x8000 | (0 << 8) | 3, (18 << 8) | 30, 0x1F, 0], slave=U)  # запис 2

# --- APN і збереження ---
c.write_registers(50, str_to_regs("internet", 16), slave=U)
c.write_register(2, 1, slave=U)             # зберегти
c.write_register(2, 6, slave=U)             # перепідключити GPRS
```

## 8. Що перевірити, якщо не працює

| Симптом | Причина / що робити |
|---|---|
| Немає відповіді | адреса (HR3), швидкість і формат 8N1, полярність A/B, термінатор на довгій лінії |
| Відповідь іноді «бита», CRC-помилки | увімкнений лог у RS485 — вимкнути (HR44 біт 0) |
| Виняток 03 на HR40…43 | IO не в режимі «вихід» (HR153…156) |
| Coil 16…22 пишеться, а пін не змінюється | порт дисплея не в режимі виходів (HR150 = 2) |
| Після перезавантаження налаштування скинулись | не виконано HR2 = 1; перевірити IR15 біт 0 (EEPROM) |
| Розклад не спрацьовує | IR10 = 0 (час не встановлено) або канал не в режимі «вихід» |
| IR3 зависає на 3 | немає мережі — дивись IR4 (сигнал) і IR5 |
| IR3 = 5, але не 6 | сервер недоступний / порт закритий / TCP вимкнено (HR44 біт 3) |
| Сервер отримує виняток 0B | пристрій на RS485 не відповідає: адреса, швидкість, HR46 |
