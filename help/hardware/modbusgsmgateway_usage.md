# ModbusGsmGateway_USAGE
# ModbusGsmGateway — функції та як користуватись

Прошивка fw 1.00. Розпиновка та знахідки по платі — у [HARDWARE.md](ModbusGsmGateway_HARDWARE.md).

## Що вміє пристрій

| Функція | Коротко |
|---|---|
| Modbus RTU slave | RS485, адреса за замовчуванням **1**, 115200 8N1. Свої регістри: стан, IO, час, конфіг |
| Шлюз GSM → RS485 | Пристрій сам підключається TCP-клієнтом до сервера, сервер шле Modbus TCP-запити; запити до інших адрес пересилаються на RS485 як Modbus RTU |
| GSM (Quectel M66) | керування живленням (PA8) і PWRKEY (PC9), мережа, GPRS, синхронізація часу NTP, SMS-команди |
| Універсальні IO | 4 піни роз'єму NFC: вхід / вхід з підтяжкою / вихід, імпульси |
| Порт дисплея | або дисплей HD44780, або 7 виходів DO0..DO6 |
| RTC | годинник на кварці 32 кГц з батарейкою, місцевий час з літнім часом |
| Планувальник | 8 записів «о HH:MM у вибрані дні → дія над IO» |
| Конфігурація | EEPROM M95512, дві копії з CRC (збій живлення під час запису не псує конфіг) |
| Індикація | 5 світлодіодів статусу, короткі звукові сигнали, кнопка |
| Дисплей | заготовка HD44780 16x2 (`set dport 1`) |
| Консоль | текстові команди по тому ж RS485 (можна вимкнути при збірці) |

## Світлодіоди

| LED | Колір | Значення |
|---|---|---|
| 1 | зелений | робота: короткий спалах раз на секунду. Не блимає — прошивка зависла (через 8 с спрацює watchdog) |
| 2 | жовтий | GSM: не світить — модем не відповідає; часто блимає — запуск / пошук мережі; подвійний спалах — проблема з SIM; повільно блимає — в мережі; світить — є інтернет (GPRS) |
| 3 | зелений | сервер: не світить — TCP вимкнено; блимає — підключається; світить — з'єднано (гасне на мить при обміні) |
| 4 | жовтий | Modbus: спалах на кожен запит (RS485 або TCP) |
| 5 | червоний | помилка: світить — є помилка (EEPROM, SIM, модем, кварц RTC); рідко блимає — час не встановлено |

Перевірка: `led 1` … `led 5` (або HR49) — горить лише вибраний світлодіод, `led 0` — назад до індикації.

## Звукові сигнали

| Сигнал | Подія |
|---|---|
| 1 короткий | контролер стартував |
| 3 коротких | старт після перезапуску через watchdog (прошивка зависала) |
| 2 довгих | на старті не знайдено EEPROM — налаштування не збережуться |
| 2 коротких | модем перестав відповідати або проблема з SIM |
| 1 довгий | скидання до заводських налаштувань |
| клац | натискання кнопки, команда `beep` |

## Кнопка (PC12)

- **Коротке натискання** — клац і рядок статусу в лог.
- **Утримання 10 с** — довгий писк і **скидання налаштувань до заводських** з перезавантаженням.

## Консоль (RS485)

Консоль і Modbus працюють на одній шині одночасно: кадр з правильним Modbus CRC обробляється
як Modbus, а текст — як команда консолі. Рядок закінчується Enter (CR або LF).

```
pio device monitor -p COM26 -b 115200 --echo --eol CRLF
```

> **Важливо.** Лог (`[ 12] gsm: ...`) — це спонтанні повідомлення в шину. Якщо на RS485 є свій
> Modbus-майстер (SCADA, панель), вимкни лог: `set log 0`, `save`. Консоль можна прибрати
> зовсім при збірці: `-D CONSOLE_ENABLE=0` у `platformio.ini`.

### Команди

| Команда | Що робить |
|---|---|
| `help` | список команд |
| `status` | стан: GSM, сигнал, оператор, IP, IO, помилки, час |
| `get` | усі параметри конфігу |
| `set <параметр> <значення>` | змінити параметр (у RAM) |
| `save` | зберегти конфіг в EEPROM |
| `reboot` / `factory` | перезавантаження / скидання до заводських (зі збереженням) |
| `io` | стан IO |
| `io <n> in\|pu\|pd\|out` | режим IO n (0..3): вхід / з підтяжкою вгору / вниз / вихід |
| `io <n> on\|off\|toggle` | керування виходом |
| `io <n> pulse <сек>` | імпульс |
| `do` | порт дисплея: режим і стан DO0..DO6 |
| `do <n> on\|off\|toggle\|pulse [с]` | вихід DO n (порт має бути в режимі виходів: `set dport 2`) |
| `time` / `time set YYYY-MM-DD HH:MM:SS` | показати / встановити **місцевий** час |
| `ntp` | синхронізувати час через інтернет зараз |
| `sched` | показати розклад |
| `sched <n> HH:MM <дні> <канал> on\|off\|toggle\|pulse [сек]` | запис розкладу n (0..7); канал 0..3 = IO0..IO3, 4..10 = DO0..DO6 |
| `sched <n> del` | видалити запис |
| `sms <номер> <текст>` | надіслати SMS |
| `reconnect` | перепідключити GPRS/TCP (після зміни APN/сервера) |
| `modem` / `modem reset` | чи ввімкнений модуль / вимкнути живлення модема на 3 с і ввімкнути знову |
| `beep` | тестовий писк |
| `led <N>` | тест: горить лише світлодіод N (1..16), `led 0` — світлодіодами знову керує контролер |

Дні в розкладі: цифри `1`=пн … `7`=нд, `*` — щодня.

### Параметри (`get` / `set`)

| Параметр | За замовч. | Опис |
|---|---|---|
| `addr` | 1 | адреса Modbus цього пристрою (1..247) |
| `baud` | 115200 | швидкість RS485 (діє після `save` + `reboot`) |
| `gwtimeout` | 500 | скільки мс чекати відповіді від RS485-пристрою (шлюз) |
| `log` | 1 | лог у RS485 |
| `dport` | 0 | порт дисплея: 0 вимкнено, 1 дисплей HD44780, 2 виходи DO0..DO6 (діє одразу) |
| `dportboot` | 0 | маска DO після старту |
| `bootout` | 0 | маска виходів після старту (біт 0 = IO0) |
| `apn`, `apnuser`, `apnpass` | internet, —, — | точка доступу GPRS |
| `pin` | — | PIN SIM-карти (якщо ввімкнено) |
| `gprs` | 1 | інтернет |
| `tcp` | 0 | підключення до сервера Modbus TCP |
| `host`, `port` | —, 502 | адреса сервера (IP або домен) |
| `sms` | 1 | SMS-команди |
| `allow1..3` | — | номери, яким дозволено SMS-команди |
| `ntp`, `ntpserver` | 1, pool.ntp.org | синхронізація часу |
| `tz` | 120 | часовий пояс у хвилинах від UTC (Київ: 120) |
| `dst` | 1 | літній час за правилом ЄС (+1 год з останньої неділі березня до останньої неділі жовтня) |

### Приклади

Перше налаштування (APN Київстар — `www.ab.kyivstar.net`, Vodafone — `internet`,
lifecell — `internet`):

```
set apn internet
set allow1 +380671234567
save
reconnect
status
```

Вихід IO2 — реле насоса, вмикати щодня о 6:00 на 15 хвилин:

```
io 2 out
sched 0 06:00 * 2 pulse 900
save
```

Будні о 8:00 вмикати IO3, о 18:30 вимикати:

```
io 3 out
sched 1 08:00 12345 3 on
sched 2 18:30 12345 3 off
save
```

## SMS-команди

Приймаються лише з номерів `allow1..3` (порівнюються останні 9 цифр, тож `+380671234567`
і `0671234567` — той самий номер). Регістр букв не важливий. Відповідь приходить SMS.

| SMS | Дія |
|---|---|
| `STATUS` | стан пристрою |
| `OUT2 ON` / `OUT2 OFF` | вихід 2: 0..3 = IO0..IO3, 4..10 = DO0..DO6 |
| `PULSE1 10` | імпульс 10 с на виході 1 |
| `SYNC` | синхронізувати час |
| `REBOOT` | перезавантаження (без відповіді) |

Вхідні дзвінки пристрій скидає. Під час ініціалізації модема **усі SMS на SIM видаляються**
(`AT+CMGD=1,4`), щоб пам'ять не переповнювалась.

## Modbus

Повна інструкція — **[ModbusGsmGateway_MODBUS.md](ModbusGsmGateway_MODBUS.md)**: параметри зв'язку, карта регістрів, команди, розклад,
шлюз через GSM, готові кадри та приклади (mbpoll, Python).

Коротко:
- RTU на RS485: адреса 1, 115200 8N1. TCP через GSM: пристрій — клієнт, підключається до сервера.
- Unit ID = адреса пристрою або 255 → сам шлюз; інший Unit ID → пересилається на RS485.
- Перед роботою з Modbus-майстром на RS485 вимкни лог (HR44 біт 0 = 0) і збережи (HR2 = 1).

## Збірка й прошивка

```sh
~/.platformio/penv/Scripts/pio.exe run            # збірка
~/.platformio/penv/Scripts/pio.exe run -t upload  # прошивка J-Link (J-Flash закрити)
```

Параметри збірки (`platformio.ini`, `build_flags`):

| Флаг | Опис |
|---|---|
| `CONSOLE_ENABLE=0/1` | текстова консоль на RS485 |
| `LED_FX_COUNT` | кількість світлодіодів для анімації |
| `SCHED_COUNT` | кількість записів розкладу (зміна ламає сумісність збереженого конфігу) |
